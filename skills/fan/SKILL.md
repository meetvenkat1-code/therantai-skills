# /fan — Divergent Escape Architecture

Second arm of the Flywheel: mandate handles flow-state (convergent, ambient, automatic); fan handles jam-state (divergent, deliberate, invoked). A jam isn't "which next step inside this frame" — the frame has run out of moves. Refinement loops can only deepen existing dimensions; one more question inside the same frame is polishing. Fan breaks frame, plural, at once.

## Core mechanic
```
JAM NODE
1. LOCATE — compress to the load-bearing stuck point, one sentence, no narrative.
2. READ DEPTH — surface dissonance vs. deep jam; governs fan width.
3. GENERATE LENSES — one exogenous framework per branch, dynamically from context. Each must:
   (a) be named, pre-existing, from a domain explicitly different from the jam's own
   (b) pass the kill-gate (below)
4. ROUTE + TRACE — run the jam through each surviving lens; every branch: framework+domain, dimension opened, exit question (not an answer).
5. SURFACE — present, never select. Recognition of "which is mine" stays with the person.
6. RE-ENTRY — committed branch → fresh seed → Flywheel mandate (compress + emit sharpest successor).
```

## The kill-gate (enforcement spine)
Dynamic lens generation risks lenses too close to the jam's own vocabulary — divergence-shaped refinement, not real exogeneity. At Step 3, before any branch surfaces: does this lens substantially overlap the jam's own terms/structure? Yes → endogenous, reject silently, regenerate. This is negative selection (kill what's too similar), not positive instruction ("be exogenous," which can be faked by surface compliance) — same architecture as an immune system killing self-similar T-cells before release.

## Branch anatomy (all three fields required, or the branch doesn't surface)
```
Branch N — [Framework] ([Domain of origin])
Dimension opened: [what this frame has that the jam's lacks]
Exit question: [one question, not an answer]
```

## Fan width (adaptive, from Step 2's depth read)
Surface dissonance: 3-4 branches. Mid-depth jam: 5-6. Deep jam: 6-8. Wider isn't always better — past a point the fan becomes a menu (selecting, not recognizing); stop where it still reads as escape routes, not a buffet.

## Convergence-trap signal (invoke even when nothing feels explicitly "stuck")
When all available moves are variants of each other rather than genuinely different directions, the frame is the problem, not the options — the sensation of exhaustive-feeling choice (2-3 options that feel complete) while none opens new territory. Fan's own forging session demonstrated this: the (a)/(b) framing of "fixed repertoire vs. dynamic generation" was itself a convergence trap, dissolved by revealing six real dimensions absent from the binary.

## What it's not
Not the Flywheel mandate (automatic/convergent vs. manual/divergent — inverses, not substitutes). Not /occam (collapses many→one; fan explodes one→many — twins, opposite direction). Not cognitive-friction-extractor (retrospective on resolved friction; fan acts live on unresolved friction). Not brainstorm (every branch structured, traced, exogeneity-verified — not a raw idea list). Not an oracle (never picks — recognition belongs to the person).

## Relations
Flywheel mandate takes over after commit (compress + ascend). Occam is the handoff when the person asks "which one?" among the branches. Cognitive-friction-extractor can name/file the resolution after fan produces it — fan produces, extractor preserves.

## Invocation
Manual only: `/fan`, "fan this," "I'm stuck/entangled," "I need a way out," "diverge from here," "expand from this node," or naming frame-exhaustion. Fires once per jam node, completes, doesn't persist — re-invoke on a new jam.

## Re-entry protocol
```
Committed branch → fresh seed → Flywheel (COMPRESS: portable handle; ASCEND: sharpest successor question)
→ momentum restored — jam converted to capital, not merely cleared
```
