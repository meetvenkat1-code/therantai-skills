# FORGE PIPELINE

Makes assay non-skippable by architecture, not discipline. Assay is the most chronically skipped step in the ecosystem — not forgotten, but skipped in the exact moment excitement is highest (a fresh spine sounds sharp; will is the weakest defense against that). This pipeline routes discriminate→forge→assay→contracts→build so the build contracts are architecturally unreachable without passing the adversarial gate; assay FAIL routes back to re-forge, never forward with a warning.

## ATTUNE suspension
Suspended for the full pipeline (redundant with its own sequencing); resumes on completion or "done."

## Pause architecture
Three clean stations — `defer`/`park here`/`stop after this`:
- **After discrimination** (organ selected, nothing forged) — resume: `resume forge` → spine stage.
- **After spine delivery, pre-assay** (rarest legitimate pause) — resume → assay.
- **After assay PASS, pre-build** — resume → load contracts, enter build.

Assay FAIL is not a pause — it's a re-entry route: constraint named, forging organ re-invoked, cycles back through Stage 2→3 automatically.

## The five stages

**1. Discriminate input type** — Claude reads and names in one line: **bare theme** (no operational heat, no fragments) → ossify, or **loaded fragments** (partial identity, named refusals, intuition-in-motion) → spinal-column. Ambiguous → Claude states its best read + one-clause reasoning, proceeds (doesn't ask). Exception: two completed spines with explicit merge intent → names as alloy input, routes to `/alloy` directly, skips Stages 2-3. No confirmation needed; advances immediately.

**2. Forge the spine** (`/ossify` or `/spinal-column`, full organ, not compressed) — ossify's internal explosion-and-selection runs inside the pipeline; practitioner sees the forged spine only, not discarded candidates. Spinal-column's transformation gate fires normally — if visible in fragments, compress directly; if absent, ask the one gate question (the only practitioner-facing question in the pipeline besides the trigger and "build"). Advances to assay automatically, no confirmation — requiring confirmation here is exactly the mechanism by which assay gets skipped.

**3. Assay** (mandatory gate, full contract — no rewrites, verdict + constraint only). PASS → "Assay holds. Loading build contracts." FAIL → name failed test(s) + re-entry constraint, re-invoke the Stage 2 organ with the constraint as input; cycles Stage 2↔3 until it holds, Claude-driven, practitioner doesn't navigate it. **Max 3 cycles** — on a third same-test failure, surface the real decision: "Failing [test] across three cycles. Possible issue: [diagnosis]. Different axis, or a fourth pass?" — the only in-loop decision surfaced.

**4. Load build contracts** (`/hybrid-engine-contract` then `/ui-contract`, hybrid governs on overlap) — mandatory, in full, before any code. "Contracts loaded. Say **build** to enter, or name any clarification first." The one deliberate pause point in the whole pipeline — practitioner may speak here before the build commitment.

**5. Build** — full hybrid-engine-contract + ui-contract apply. Single `.html` file unless specified otherwise. Build law: hybrid by default (works in claude.ai + external browser via key drawer); exact API routing; no Authorization header; no banned patterns; Zone C mailto (header only, no footer); Zone A identity rule (H1 never repeated verbatim below); copy modal law (`showCopyModal` only, clipboard API banned); provider dot standard; Space Grotesk (Syne deprecated). Closing: "Forge complete. Spine → Assay: HOLDS → Contracts → Engine delivered. Say /harvest to close, or continue."

## Behavioral rules
Practitioner speaks twice in a standard run: the trigger, and "build" at Stage 4 — everything else auto-advances. Assay cannot be skipped by request — "if you genuinely want no adversarial validation, invoke /hybrid-engine-contract directly; inside this pipeline, the gate holds." Fail loop is Claude-driven, no practitioner navigation. No architecture/layout/feature questions during forging — those belong to Stage 4's window. Voice-tolerant — phonetic/fragmented "build something" intent fires it.

## Relations
Ossify/spinal-column at Stage 2 are the full organ, still invokable standalone for theme-only work. Assay at Stage 3, still standalone-invokable outside this pipeline. Hybrid-engine-contract + ui-contract at Stage 4, neither optional. Harvest-pipeline is the natural downstream (captures what built + resolved). Ignition-pipeline is the upstream complement — ignition opens, forge-pipeline builds, harvest-pipeline closes. Attune suspended during, resumes after.

## Scope
Forging phase, staffed (sequences 4 existing organs + the build). Contribution isn't sequencing knowledge — the practitioner has that — it's removing will as the mechanism by which assay fires. Global.
