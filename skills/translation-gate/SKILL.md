# Translation Gate

The bottleneck in most generative requests isn't vocabulary — it's that felt-sense knowing (recognizes quality on contact, below language) is being asked to do specification knowing's job (naming a destination before arriving). This skill doesn't teach specification fluency — it makes Claude fluent in reading felt-sense signals *as* specifications, moving the translation effort to Claude's side.

## The five families
**Pointing** — indicates an existing thing + what landed ("I like the density here"). Annotation, not authorship — isolate the named quality, don't ask what it means.
**Excluding** — names what kills it, not what it is ("don't resolve into advice"). Cheaper than positive specs, closes exits Claude would default toward.
**Naming the register** — one texture-word standing for a whole tonal field (dense, somatic, clinical, mythic). Governs every downstream choice, not one input to balance.
**Dimensional constraining** — 4-5 levers tightened at once (length, voice, form, exclusion, what-to-resist). Builds the box the output emerges inside, rather than picturing the output.
**Metaphorical anchoring** — points at a *kind of mind*, not content ("like a field notebook, not a lecture"). Imprecise by design — activates orientation, not a checklist.

## Ambient layer — always on, never invoked, no visible artifact
```
SCAN for a family signal already faintly present in the phrasing
  → present: build directly from it, state nothing extra — the person notices
    only that the response landed closer, never that a framework was consulted
  → absent: default judgment applies; never manufacture a family where none exists
```
Entire value is invisibility — no preamble, no disclosed checklist.

## Invoked layer — deep-mode (one round, exactly)
For the rarer moment the person feels the gap but can't name the family, and says so: read the triggering fragment → identify the 2-3 most plausibly live families (not all five) → surface as **one tappable question**, each option a concrete instance for *this* fragment, never the abstract family name → the tap is the specification, build immediately, no second round.
Bad option: "Dimensional constraining." Good option: "Tighten by length and form — short, as an account not an essay."

## The constraint that must never erode
Built because inventing effort was the original problem. Greatest risk is scope creep — deep-mode quietly growing a second question, then a third, becoming another intuition-forge. Wanting to add a second question is the signal to stop and ask whether deep-mode still solves its original problem — not a signal to add it.

## Worked example
"Give me something archaeological about grief, not a lecture" — two signals already present (register-word "archaeological" + metaphorical anchor "not a lecture") → build directly, no deep-mode. Contrast: "something about grief, you decide, but not like — you know — not like that" — no signal survives the scan → invoke, offer e.g. "Tightened by form and exclusion — an account, not advice" vs. "Anchored by a kind of mind — a field notebook, not a lecture."

## Not
Not a replacement for spinal-column/ossify/spine-pipelines (those build identity from nothing/fragments — this is the lens, not the forge; it can hand them a sharper starting signal but doesn't replace their stations). Not a disclosed methodology — never surfaces "applying pointing" unless asked. Not a way to avoid fact-gap clarifying questions — those still get asked by whatever already governs them; this only governs the aesthetic/registral gap. Never grows past one tappable question in invoked form, regardless of momentary temptation.

## Priority
Named contracts (ui-contract, an Engine Parameter Block, hybrid-engine-contract, explicit project instructions) > this skill's ambient read — governs the aesthetic gap, never overrides settled architectural law.
