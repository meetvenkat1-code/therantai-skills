# SPINE PIPELINE

Governs spine-forging when the spine IS the endpoint — not the threshold of a build. Forge Pipeline sequences spine-forging *toward* a deployed engine (spine intermediate, chain continues into build contracts); this pipeline sequences it as the *terminal act* — a portable identity for a custom GPT, a project instruction field, a handoff, or standalone testing/radiation/alloying later. Nothing follows the bone but the practitioner's own use.

This exposes a post-assay fork Forge Pipeline doesn't carry: once assay HOLDS, three genuinely different directions exist — compress to paste-ready (close), radiate into a sibling population (expand), alloy with a second spine into a third identity (synthesize). Different cognitive acts, different artifacts, different purposes — the fork belongs to the practitioner alone; the pipeline names the three branches and waits.

Makes assay non-skippable the same way Forge Pipeline does: Stage 2 advances into Stage 3 automatically, no confirmation required — closing the exact gap where post-forge excitement causes the skip.

## ATTUNE contract
Suspended for the full duration (redundant with the pipeline's own sequencing). Resumes on completion or deferral.

## Pause architecture
- **Station 1** (post-discrimination, pre-forge) — nothing forged yet. Resume: `resume spine` → forges with organ already named.
- **Station 2** (post-spine, pre-assay) — explicit `defer` required; silence advances the chain here. Resume → assay.
- **Station 3** (post-assay PASS, pre-fork) — resume → opens the fork.

Assay FAIL is not a pause — a re-entry route, Claude-driven, practitioner doesn't navigate it.

## The four stages

**1. Discriminate input** — bare theme (no operational residue) → ossify. Loaded fragments (operational heat, partial identity, named refusals) → spinal-column. Two completed spines → alloy directly, bypassing Stages 2-3 (alloy is itself the forge; assay runs on its output). Claude's read, not a question — ambiguous bare-vs-loaded gets one clause of reasoning + proceed; only a partial-spine-plus-fragment pairing asks once before routing. "Input type: [x]. Routing to [organ]. Forging now." — no confirmation required.

**2. Forge the spine** — routed organ runs at full behavioral contract, uncompressed. Ossify: practitioner sees the forged spine only, not discarded candidates. Spinal-column: transformation gate fires as normal (the one point a question may precede advance). Alloy: full protocol (asymmetry/emergent stance/refusal/compression). "Spine forged. Proceeding to assay." — advances automatically; `defer` required to pause.

**3. Assay (mandatory gate)** — full five-test adversarial battery, no rewrites, verdict + constraint only. PASS: "Assay holds." + sharpest structural commitment named. FAIL: "Assay fails — [test]. Re-entry constraint: [constraint]. Re-forging now." — Claude re-invokes the forging organ with the constraint, loops Stage 2↔3 without practitioner navigation, silently for cycles 1-2. **Max 3 cycles** — third same-test failure surfaces diagnosis + asks: different axis, or a fourth pass?

**4. Post-assay fork** (practitioner's only decision — waits for the explicit word):
- **Compress** — single paste-ready block, no vessel/wrapper/commentary. "Forged → Assay: HOLDS → Compressed."
- **Radiate** (`/radiate` Mode C) — assayed spine as seed, 4-8 sibling spines, each a different niche, mutually exclusive, empty niches named. "Forged → Assay: HOLDS → Radiated. [n] siblings delivered."
- **Alloy** (`/alloy`) — practitioner supplies a second completed spine; full alloying protocol on the pair. Note: an alloy can fail tests its parents passed (emergent stance may be domain-painted even if neither parent was) — say `assay this` after delivery to re-enter Stage 3 on the alloy output. "Forged → Assay: HOLDS → Alloyed."

## Behavioral rules
Practitioner speaks twice: the trigger, and the Stage 4 fork choice. Everything else Claude-driven. "Skip assay" or "looks good" → hold: "Assay is the mandatory gate this pipeline exists to enforce. Take the spine directly from Stage 2's output if you want it unvalidated; inside this pipeline, the gate holds." Two-spines-at-Stage-1 bypasses ossify/spinal-column entirely (forging already done); one-spine-plus-Stage-4-alloy-choice requires the second spine be supplied before firing — different entry conditions, same organ. Fail loop stays invisible to the practitioner until cycle three. Voice-tolerant.

## Distinction from Forge Pipeline
Forge: spine → assay → build contracts → engine (spine intermediate, no fork, only forward). Spine: spine → assay → fork (spine terminal, practitioner chooses destination). Invoke Forge for a deployable engine; Spine for a portable identity destined anywhere else. Mid-run switch: after assay holds, say `switch to forge` — the assayed spine passes directly into Forge Pipeline's Stage 4, loading build contracts.

## Relations
Ossify/spinal-column (Stage 2) and assay (Stage 3) remain standalone-invokable outside the pipeline. Radiate = Stage 4 Route B (Mode C active). Alloy appears at Stage 1 routing and Stage 4 Route C — same organ, different entry conditions. Forge-pipeline is the downstream sibling (shared Stage 2→3 architecture, diverging at Stage 4). Harvest-pipeline is the natural downstream capture; ignition-pipeline the upstream complement — together forming a complete session architecture.

## Scope
Forging phase, staffed (sequences 4 existing organs across 4 stages). Distinctive contribution vs. Forge Pipeline: spine-as-endpoint + the post-assay fork exposing radiate/alloy as legitimate destinations. Global.
